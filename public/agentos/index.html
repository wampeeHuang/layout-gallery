01 / SYSTEM LOGIC

不是多一个工具，
是少一点盯着。

AgentOS 的目标很克制：把“记得做、看着跑、出问题再修”这类人工注意力，改造成文件化、可调度、可验证的系统动作。人保留方向决策，Agent 接管重复执行。

01 / DECOUPLED

Agent 解耦

调度不感知执行者。换模型、换 Agent、换管线，系统仍然按同一组约定继续工作。

02 / FILE-FIRST

真相在文件

工具、项目、知识都有明确的源文件。网页和面板是派生视图，不另建一份会漂移的数据库。

03 / HUMAN-GUIDED

人是监理

AI 是第一公民，人不再充当操作员。系统负责推进，人负责确认边界、判断方向与处理例外。

02 / CONTROL PLANE

五个模块，
各自负责一件事。

从工具发现到异常沉淀，每个模块都拥有清晰边界。点击左侧模块，查看它的职责、关键判断和来自原始网站的真实界面预览。

01 / AGENTBOARD

文件即注册，状态即界面。

Agentboard 是全部工具的管理中枢：工具通过 manifest 自发现，人在面板里看状态，Agent 通过 API 直接调用。

WHY IT MATTERS不需要再维护第二套配置。
  • 自发现注册 —— Agent 写 manifest，工具架自动发现
  • 双平面架构 —— MCP 给 AI，REST 给人和系统
  • 状态可见 —— 绿色在跑，灰色未启动，一眼即知
  • 零残留下架 —— 删除项目文件夹即可退出系统

根因非直觉只有那些“看起来应该能跑、实际上总会踩坑”的问题，才进入知识库。
修复可复用每条记录带明确修复步骤，让 Agent 在下一次对话前先加载经验。
同类错误不再重复知识库不是收藏夹，而是系统的反复验证层。

05 / SOURCE OF TRUTH

把复杂度放进约定，
不要放进人的记忆。

AgentOS 的控制力来自边界：定义写进文件，视图由文件派生，运行时再接受巡检。这样换工具、换页面、换 Agent，都不会让系统失去方向。

  1. 01定义层：manifest、.project、Markdown 是源文件。
  2. 02控制层：Agentboard、Scheduler、Supervisor 协调运行。
  3. 03证据层：Inspector 与 Tips 让状态可验证、经验可回收。
